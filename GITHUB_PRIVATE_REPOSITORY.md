# 🔒 Как сделать репозиторий приватным в GitHub

## ✅ Да, можно и нужно!

Особенно важно для проектов с секретными ключами (REST API Key, Firebase keys и т.д.).

---

## 🚀 Как сделать репозиторий приватным

### Если репозиторий еще не создан:

1. При создании нового репозитория:
   - Выберите **"Private"** вместо "Public"
   - ✅ Готово!

### Если репозиторий уже создан (Public):

#### Вариант 1: Через GitHub веб-интерфейс

1. Откройте ваш репозиторий на GitHub
2. Перейдите: **Settings** (в верхнем меню)
3. Прокрутите вниз до раздела **"Danger Zone"**
4. Нажмите **"Change visibility"**
5. Выберите **"Make private"**
6. Подтвердите действие (введите название репозитория)

#### Вариант 2: Через GitHub CLI

```bash
gh repo edit --visibility private
```

---

## ⚠️ Важно перед изменением на приватный!

### 1. Проверьте `.gitignore`

Убедитесь, что секретные файлы не попадут в Git:

```gitignore
# Environment variables
.env
.env.local
.env.production
.env.development

# Firebase keys
*-firebase-adminsdk-*.json
frebaze-*.json

# API keys (если есть в коде)
**/keys/**
**/secrets/**
```

### 2. Проверьте историю коммитов

Если вы случайно закоммитили секретные ключи:

#### Шаг 1: Удалите файлы из истории

```bash
# Удалить файл из истории Git
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch .env.local" \
  --prune -- --all

# Или используйте BFG Repo-Cleaner (быстрее)
bfg --delete-files .env.local
```

#### Шаг 2: Force push (осторожно!)

```bash
git push origin --force --all
```

⚠️ **Внимание:** Это перезапишет историю. Убедитесь, что никто другой не работает с репозиторием!

#### Шаг 3: Создайте новый ключ

Если REST API Key был в истории - **создайте новый** в OneSignal:
1. OneSignal Dashboard → Settings → Keys & IDs
2. Удалите старый ключ
3. Создайте новый ключ

---

## 🔐 Что должно быть приватным?

### ✅ Должно быть в `.gitignore`:

- `.env.local` - переменные окружения
- `*.json` с ключами (Firebase Admin SDK)
- `key.properties` - ключи для подписи Android
- Любые файлы с секретными ключами

### ✅ Можно коммитить:

- `package.json` - зависимости
- Исходный код (без ключей)
- Конфигурационные файлы (без секретов)
- Документация

---

## 📋 Чек-лист перед публикацией

Перед тем как сделать репозиторий публичным (или если он уже публичный):

- [ ] Проверьте `.gitignore` - все секретные файлы игнорируются
- [ ] Проверьте историю коммитов - нет ли секретных ключей
- [ ] Убедитесь, что REST API Key не в коде
- [ ] Убедитесь, что Firebase Admin SDK ключи не в репозитории
- [ ] Проверьте, что `key.properties` не закоммичен
- [ ] Если нашли секреты в истории - удалите их и создайте новые ключи

## 🎯 Рекомендации

### Для приватного репозитория:

✅ **Можно:**
- Хранить примеры конфигурации (`.env.example`)
- Коммитить код с переменными окружения (но не значения!)
- Делиться с командой через GitHub

❌ **Нельзя:**
- Публиковать секретные ключи
- Коммитить реальные `.env` файлы
- Показывать REST API Key в коде

### Для публичного репозитория:

⚠️ **Еще строже!**
- Все секреты должны быть в `.gitignore`
- Используйте GitHub Secrets для CI/CD
- Никогда не коммитьте реальные ключи

---

## 🔍 Как проверить, что секреты не в репозитории?

### Проверка через Git:

```bash
# Поиск потенциальных секретов
git log --all --full-history --source -- "*env*"
git log --all --full-history --source -- "*key*"
git log --all --full-history --source -- "*secret*"
```

### Проверка через GitHub:

1. Откройте репозиторий на GitHub
2. Используйте поиск: `ONESIGNAL_REST_API_KEY` или `os_v2_app_`
3. Если нашли - удалите из истории!
